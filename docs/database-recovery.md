# 本地数据恢复

SpeakMore 启动时先检查数据库。升级前备份没有成功、迁移失败、数据损坏或版本不兼容时，会停留在恢复页；此时不会启动模型管理或听写服务，也不会用空数据库覆盖已有文件。

## 先判断提示

| 提示                                   | 处理方式                                                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 无法完成升级前备份                     | 检查磁盘可用空间和数据目录权限，再点击“重新打开应用”。本次未执行数据升级。                                                                         |
| 本地数据升级未完成                     | 先退出应用、保留原数据目录。重新打开仍失败时，使用修复后的应用版本重试。整次迁移在一个事务中，正常回滚后仍是原版本；保留的升级前备份用于额外恢复。 |
| 数据来自更新版本                       | 使用创建该数据库的同版或更新应用。不要让旧版直接打开或清空新版数据库。                                                                             |
| 数据损坏、无法识别                     | 退出后另存整个数据目录，保留可能存在的 WAL/SHM/journal 文件。不要直接删掉日志文件或建立空库；先确认可用备份。                                      |
| 主数据库缺失或为空，但恢复目录仍有文件 | 应用会停止初始化，以保留可能唯一剩余的数据副本。确认现有文件和备份后再恢复。                                                                       |
| 升级备份尚未清理                       | 主数据库可继续使用，但备份可能仍包含历史记录。检查目录权限，下次启动会重试清理。                                                                   |

“查看数据文件”通过 macOS Finder 显示当前应用固定的数据目录，不上传任何内容。实际路径为 `~/Library/Application Support/com.speakmore.desktop/data`。主库为 `speakmore.sqlite3`；升级备份位于 `speakmore.sqlite3.recovery` 文件夹。

## 恢复备份的顺序

以下为故障处理步骤，当前没有一键替换数据库入口。操作前应由维护者核对备份和应用版本。

1. 完全退出 SpeakMore，确认其他版本的 SpeakMore 也没有打开同一数据目录。仅关闭主窗口会隐藏应用，不等于退出。
2. 在本机另存整个现有 `data` 目录，保留主文件、SQLite 日志与恢复文件夹，使用有足够空间且受当前用户账户保护的位置。这份副本用于保留故障现场。
3. 选择 `before-vN-to-v7.sqlite3` 的完整备份；旧版升级可能保留 `before-vN-to-v6.sqlite3`、 `before-vN-to-v5.sqlite3` 或 `before-vN-to-v4.sqlite3`，需核对其版本与时间。`pending-UUID.sqlite3` 及其日志是中断的临时文件，不能当作已完成备份。完整备份应单独通过 SQLite `integrity_check`、`foreign_key_check` 和 `user_version` 校验；只读检查不能执行迁移。
4. 在独立临时目录复制该备份，并用与该 schema 相容的修复版应用或维护工具验证所需设置、词典、历史和使用统计。不要用已有迁移缺陷的同一个版本反复覆盖数据；备份不保证修复程序本身的迁移错误。
5. 确认恢复对象后，由维护者在应用完全退出的条件下保留旧目录，并以经过验证的副本恢复主库。旧库的 WAL/SHM/journal 不能混入恢复后的数据库，也不能在应用运行时替换主文件。没有合适备份时保留原文件，继续诊断，不宣称恢复成功。
6. 重新启动相容版本；核对数据与当前模型。模型文件不属于数据库备份，应用仍会按受信清单重新验证。缺失或损坏的模型需要重新下载或导入，不代表历史恢复失败。旧许可证行可能包含在数据库备份中，本期不解析、不验签，也不以其限制功能。API Key 不在数据库备份中；恢复后的旧 reference 若已清理，需重新输入密钥并测试连接。测试记录也在库中，须与配置及凭据版本匹配后才能恢复；旧时间戳不能代替测试资格。

备份只保护迁移时刻的本地数据，成功升级后会清理，不是长期版本历史。清空历史属于逻辑删除，不保证移除系统备份、磁盘残留或已被用户另存的副本。备份仍为本地明文，包含当时已保存的历史、设置和签名许可证，不包含模型、音频和 Keychain 中的 API Key；请不要把真实数据库附到公开问题或日志中。初始 license 表仅为旧数据兼容保留；数据库当前因文字整理回退原因升级为 v7。本期无订阅、支付或付费激活。

## 开发验证

`cargo test -p speakmore-core --lib` 包含跨多版本回滚、WAL 内容备份、独立副本重开、备份失败、损坏/未知/新版拒绝、配置验证失败、私有权限与链接边界、成功后清理及缺失主库保护。v4 → v5 专项验证 AI 配置保留、重新测试要求、关闭整理，以及最后一步失败时恢复原字段和开关；v5 → v6 专项验证旧测试时间保留但不授予新资格、配置/历史开关保留、关闭整理，以及末步失败回滚新增列并保留可独立重开的 v5 备份；桌面 lib tests 验证恢复状态不暴露路径。

`crates/core/examples/recovery_fixture.rs` 仅用于独立应用标识下的合成数据库，故意制造 migration 004 冲突，拒绝覆盖现有文件；不属于产品入口，不使用真实录音或用户数据。应用安装、物理断电及事务内部崩溃仍须单独验收。

2026-09-16 已补充 [真实磁盘满与提交后崩溃验证](./macos-database-faults.md)：历史与使用统计一起回滚，重试只保存一次；提交后终止保留 WAL 并正常恢复；升级备份空间不足时原 v6 数据和已有备份不变，释放空间后升级至 v7 并保留 1,024 条合成历史。该验证不覆盖物理断电、事务内部终止或安装器升级。
