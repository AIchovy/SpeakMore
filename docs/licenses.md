# 离线许可实现

> 历史研究归档（2026-09-16）：用户已明确本期不接订阅、支付或付费激活，并移除次数和 Pro 限制。以下是早期实现记录，不是当前产品合同。当前桌面/core 已移除许可依赖、启动验签、导入/移除 IPC 与相关 UI；独立验签 crate 保留作研究，旧数据库行保留不参与功能判断。后续买断方案另行设计。

macOS 客户端已实现许可证离线验签、导入、更换、移除、重启恢复与原生 Pro 权益。免费版每日 20 次有效结果，Pro 不限次数；两者都可使用全部已发布的本地 ASR 模型，单次最多 5 分钟。下载与使用 Whisper / SenseVoice 不要求购买或登录。

当前仍是开发预览。文字整理已接入真实会话，仍需真实服务质量验收；支付服务、订单与邮件履约、退款处理和正式发布签名尚未完成。没有购买入口，也没有签发生产许可证来模拟订单成功。以下是客户端实现与验证记录，不代表完整商业验收。

## 签名和格式

`crates/license` 不访问网络、系统时间、设备信息、存储或 IPC。它使用锁定的 `ed25519-dalek 2.2.0`，调用 `verify_strict` 验证原始载荷，并在加载公钥时拒绝弱公钥。严格验签的具体边界依据 [VerifyingKey 文档](https://docs.rs/ed25519-dalek/2.2.0/ed25519_dalek/struct.VerifyingKey.html#method.verify_strict)；算法定义见 [RFC 8032](https://www.rfc-editor.org/rfc/rfc8032.html)。

```text
token = base64url_no_pad(payload_bytes) + "." + base64url_no_pad(signature)
signed_bytes = UTF8("SpeakMore-License-v1\0") || payload_bytes
signature = Ed25519.sign(private_key, signed_bytes)
```

载荷是一个 JSON 对象，必须且只能含这些字段：

| 字段              | 限制                                                   |
| ----------------- | ------------------------------------------------------ |
| schema            | 整数 1                                                 |
| key_id            | 1–64 个小写 ASCII 字母、数字或连字符，必须匹配内置公钥 |
| license_id        | 规范化、非 nil 的 UUID 字符串，不含购买邮箱            |
| product / edition | 分别为 speakmore / pro                                 |
| major_version     | 整数 1，表示已购 1.x 可长期使用并包含 1.x 更新         |
| issued_at         | 非负 i64 Unix 秒，仅作记录，不作为失效日期             |

服务端只序列化一次，客户端验证同一组 bytes，不先排序字段或重新序列化。原始提交最多 8192 bytes，在裁去首尾空白之前检查；不允许内部空白、填充符或多余分隔符。Base64 使用 [URL_SAFE_NO_PAD](https://docs.rs/base64/0.22.1/base64/engine/general_purpose/constant.URL_SAFE_NO_PAD.html)，签名解码后必须为 64 bytes。严格结构解析拒绝重复字段（包括转义后的重名）、未知字段、错误类型和尾随 JSON。

验签成功产生不可反序列化的 `VerifiedLicense`，字段私有，Debug 隐去 token；签名 token 使用 Zeroizing 持有。其本地存储读取方法仅供原生层使用。WebView 只收到 free / invalid / pro 状态及许可编号、签发日期等必要元数据。不能通过前端提交 Pro 布尔值制造权益。

永久许可不依赖机器时钟判定到期；未来的 issued_at 不使有效签名失效。界面由 Rust 转换为 UTC 日期，超出日期表示范围则显示“日期无法显示”，不在前端解释不安全整数。

## 导入、移除和启动

`activate_license` 和 `remove_license` 仅允许主窗口调用，均需 `expected_revision`。原生会话 actor 的设置预约使许可操作与录音、其他设置事务互斥；期间按住的快捷键不会在完成后突然开启录音。

导入先验签，再在 SQLite Immediate 事务中核对设置修订号，写入既有 license 表并递增设置修订。提交成功后才发布原生权益。相同 token 的重复导入不改变修订号或导入时间。无效 token、并发冲突或已确认的事务回滚保留原许可；若底层提交结果不确定，内存维持旧状态，重启重新读取实际持久结果，不承诺磁盘一定未变化。

移除在同一事务删除当前许可并关闭文字整理，不删除历史、模型或用量。重新导入也不会重置用量。导入不会自动开启云端、选择 AI 服务或开启整理。SQL 操作一旦入队，由原生层完成，不随 WebView 关闭而丢弃。

启动重新验签保存的 token。SQL 先对类型与 byte 长度设限，再读取最多 8 KiB 的文本；损坏 UTF-8、BLOB、超长、未知公钥或签名无效时保留记录、提示原因并恢复免费权益。实际数据库错误继续走存储恢复流程，不能把整个损坏数据库伪装成无许可。

许可复用初始 license 表，无许可专用迁移；数据库现随文字整理回退原因升级为 v7。签名 token 存在本地明文 SQLite，也包含在升级备份中；API Key 仍单独位于系统凭据库。移除许可不保证从用户自行保存的备份或磁盘残留中删除。恢复步骤见 [本地数据恢复](./database-recovery.md)。

## 会话中的权益

数据库视图分别携带可展示的 LicenseStatus 和不可伪造的已验证许可引用。actor 使用后者判断资格，并在开始时冻结会话视图。免费版达到 20 次时阻止新录音，已有结果仍能读取与复制；Pro 可生成第 21 次及后续结果，录音仍为 300,000 ms 上限。

用量写入失败时，已生成文字仍保留。免费版要求修复记账后再录音；已验证 Pro 可继续使用。移除许可后，如果记账故障尚未修复，则恢复免费版存储保护。一般配置读取失败仍会阻止 Pro 开始，防止在数据策略不明确时录音。

已验证 Pro 许可现可在“写作模式”中单独开启整理；同时要求所选 AI 服务具有匹配测试记录、可读取凭据与明确的数据同意。会话冻结原生许可资格，前端不能自报 Pro。开启及移除许可在听写期间返回 Busy；关闭整理和收紧隐私策略立即作用于在途请求。失败保留原文，不多计一次用量。

## 公钥与操作密钥

`resources/license-trust.json` 目前包含独立公钥 `lic-2026-01`，在构建时检查并内嵌进原生客户端。信任集合最多 16 个公钥、总文件最多 16 KiB，不允许重复 ID、未知字段、错误长度或弱公钥。模型、许可与更新使用不同签名域和密钥。

`scripts/license-keygen.mjs` 是维护者工具，不打包、不在应用启动时运行。它生成独立 Ed25519 密钥，将 PKCS#8 私钥排他写入权限 0600 的文件，公钥排他写入新的信任文件；拒绝覆盖已有输出。新建父目录为 0700，直接父目录必须是真实目录，现有父目录权限需维护者检查。内容写入后 fsync，不把密钥输出到终端。

本地生成的私钥位于忽略的 `.cache/signing/license-2026-01.pem`；已仅通过文件属性确认文件 0600、目录 0700，没有展示私钥内容。该缓存文件不是生产托管或备份方案。发布前须建立独立受限签发环境、可靠备份与恢复验证；私钥不能进入 App、前端、日志或代码仓库。工具清零导出的 Buffer，但不承诺 Node/OpenSSL 中所有内部副本都已清零。

两个输出不是跨文件原子事务。中断或第二个输出失败时可能仅留下私钥，应保留并核对现场，不能覆盖旧密钥后假装恢复成功。轮换使用全新 ID 和两个新路径生成，再将新公钥追加到现有信任集合；先分发认识新公钥的客户端，再用新私钥签发。保留旧公钥以继续支持已购许可，不能用新信任文件直接覆盖旧集合。

首版不做设备计数、在线校时、后台激活或联网吊销。退款后停止补发和后续履约不能保证撤销已导入的离线 1.x 许可。高级用户修改本地文件、时钟或二进制的能力仍存在；不会据此宣称防破解或在线撤销已完成。
