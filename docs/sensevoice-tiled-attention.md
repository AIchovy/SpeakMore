# SenseVoice 完整上下文注意力分块实验

2026-09-16。该实验针对 [五分钟内存调查](./sensevoice-memory.md) 中的长序列注意力分配，在独立模型图中分块计算查询行。候选图保存在项目缓存中，原始模型、受信模型目录及用户数据不变。后续已增加独立 worker profile，候选尚不作为可下载模型发布。

## 计算方式

原图每层生成完整的 `Q × Kᵀ`、掩码和 Softmax 张量。实验将 **查询行按 128 行分块**，每一块仍与完整的 K/V 计算，并保留原有缩放、两次掩码及 Softmax 的最后一轴。70 层注意力均使用相同转换；其他节点、所有原有 initializer 和模型元数据保留。该推理仍接受一次完整音频，不拼接识别片段，不截短 300 秒录音，也不改变音频内部时间关系。

最后不足 128 行的查询只在计算图中补零，键和值不补零；每轮产生固定大小输出，以 Loop scan 汇总、恢复批次/注意力头/时间顺序，最后去掉补出的查询行。Softmax 仍沿完整键序列归一化，因此这种查询行分块在数学上保持原注意力定义；浮点实现、原生结果和性能须另外验证。机制依据：[ONNX Softmax 13](https://onnx.ai/onnx/operators/onnx__Softmax.html#softmax-13)、[ONNX Loop](https://onnx.ai/onnx/operators/onnx__Loop.html)。

导出器仅接受已锁定模型的大小和 SHA-256，拒绝未识别结构、改变 Softmax 轴或被外部消费者复用的中间值。转换后检查所有原 initializer 的序列化摘要未变，并通过 ONNX checker。原图采用 IR 7 / opset 13，候选保持相同版本，不引入自定义算子或额外原生动态库。

## 当前数值与原生证据

代数单元对照采用 ONNX 1.17.0、Python ORT 1.23.2、NumPy 2.2.6；15 组涵盖长度 1/127/128/129/263、batch 1/2、部分及全部掩码。候选与原表达式的最大绝对差均为 0，输出形状相同且有限。此检查仅验证局部代数，不能代替产品原生运行时。

完整音频由产品锁定的 sherpa-onnx 1.13.8 / ORT 1.28.2 C API 运行，CPU 4 线程；同一进程复用 recognizer，每次释放 stream/result。每次完整 300 秒英语输入仍只调用一次 decode，使用原公开 fixture 加 1 秒停顿后循环至 4,800,000 samples。

| 原生配置             | 完整 300 秒次数 | 单进程最大 RSS                  | 峰值 physical footprint | decode 时间                 |
| -------------------- | --------------- | ------------------------------- | ----------------------- | --------------------------- |
| 原图，上一轮连续对照 | 3               | 2,345,910,272 bytes / 2.185 GiB | 见原测量记录            | 33.811 / 32.333 / 32.635 秒 |
| 分块候选，首次       | 1               | 1,226,326,016 bytes / 1.142 GiB | 892,978,568 bytes       | 32.137 秒                   |
| 分块候选，连续       | 3               | 1,375,141,888 bytes / 1.281 GiB | 1,116,489,120 bytes     | 31.773 / 33.453 / 36.192 秒 |

三次连续候选的最大 RSS 比此前默认序列低约 41%；这是单进程实验对照，不是整应用或最低机型承诺。没有控制系统负载、内存压缩或热状态，不据此推导 P95 或微小速度差异。4 次候选英语结果均与既有基线 SHA-256 一致：`67658f46ee7ca478852d1770349001892c8665696429fd7931b64698940657cb`，2,570 bytes、37 次预期片语。

另以全新进程分别运行原图和 128 行候选：普通话/英语/粤语/日语/韩语各显式语言与自动检测、300 秒重复普通话、300 秒五语言混合、长音频后的短英语，共 **13 对 / 26 次 native decode**。全部原生 JSON 结果字段逐项一致，包括 text、tokens、timestamps、lang、emotion、event、durations、words、ys_log_probs；空字段也保持一致。原图序列最大 RSS 2,301,624,320 bytes（约 2.144 GiB），候选 1,312,489,472 bytes（约 1.222 GiB）。

该序列的普通话 / 混合长音频分别耗时：原图 30.960 / 30.146 秒，候选 32.840 / 43.756 秒。混合项出现明显耗时上升，不能只报告内存收益或把单次值当成延迟门槛通过。后续计算块选择和性能验收必须同时记录内存、处理时长与完整结果。数值、原始报告摘要与工具源码摘要见 [实验记录](./evidence/sensevoice-tiled-attention-2026-09-16.json)。

候选模型：239,537,160 bytes，SHA-256 `d1c2b929e93c15bfcb705f1f6edb3fc6403039bfe625e5662da03beb9e95ea28`。它具有不同的产物身份，不能覆盖原目录项或复用原 artifact 哈希。

### 256 行对照

考虑上述耗时变化，另行生成 256 行候选：同样 70 层转换、15 组局部代数对照最大差为 0；候选大小 239,537,160 bytes，SHA-256 `46346d31c9314b4873aa16882f20955774cda4048a849c80db2a27117569a3d8`。再次在两个独立进程完整执行相同 13 对原生用例，全部 JSON 结果字段一致。

该序列原图最大 RSS 2,301,460,480 bytes，256 行候选 1,326,055,424 bytes（约 1.235 GiB）；候选峰值 footprint 973,817,368 bytes。普通话 / 混合长音频耗时分别为原图 31.667 / 33.165 秒、候选 32.040 / 32.372 秒。此对照使 256 行成为后续验证候选，但仍不能由两个不同时间的序列宣称已经达到 P95 或保证比 128 行更快。

随后独立运行 256 行候选的连续三次完整 300 秒英语：34.030 / 32.062 / 33.135 秒，单进程最大 RSS **1,178,288,128 bytes / 1.097 GiB**，峰值 footprint **1,137,018,248 bytes**。三次文本摘要均与上述英语基线相同。256 行两种序列中更高的 RSS 是多语言序列的 1.235 GiB；不只取更小的一次作为其资源上限。本轮两个配置合计完成 26 对多语言结果比较，全部原生 JSON 一致。

后续以 256 行图作为完整 worker/profile 与整应用验收候选。该选择基于已测结果，不承诺最终发布配置；原生诊断对照之外的 worker 验证单独记录，不由此推导自然语料、最低机型或整个应用的同时占用。

以最终转换器重新生成 256 行图，模型字节摘要和生成报告均与第一次相同。输入大小、摘要和符号链接拒绝检查通过。生产目录仍为原有三个条目；没有增加未验收的下载项，也没有更换既有应用包。

## 完整 worker 验证

新增 `sensevoice-tiled256-v1`，沿用逻辑模型 ID，但要求独立版本与 bundle 安装身份；目录、协议和原生加载均绑定上述 256 行图的大小与摘要。原 `sensevoice-v1` 保留。两种 profile 的转写请求必须与已加载配置相同，错误标签不会借用另一张图执行。CPU 线程、VAD、ITN、词典能力、语言和 300 秒上限不变。设置页只接受已签名生产目录中的模型，该候选尚不可下载或导入。

2026-09-16，在真实 Supervisor → stdio → worker → VAD → native decode 链路完成 **2 项集成测试**，总用时 224 秒。普通话、英语、粤语、日语、韩语短句，以及 300 秒重复英语、300 秒五语言混合，共 7 对结果的完整文本和语言字段一致；每次完整音频只收到一个最终结果，字典版本、使用/省略数量及 NeedsReview 正确。工作线程的时长包括传输与前处理范围内的计时，不等同于前文诊断程序的纯 decode 时长。

| 完整 worker 输入 | 原图 ASR 时长 | 256 行候选 ASR 时长 | 文本对照                         |
| ---------------- | ------------- | ------------------- | -------------------------------- |
| 300 秒重复英语   | 31.399 秒     | 34.077 秒           | 相同，2,720 bytes、37 次预期片语 |
| 300 秒五语言混合 | 31.651 秒     | 34.328 秒           | 相同，596 bytes                  |

候选本次耗时更高；这不是 P95 或固定延迟承诺。五语言混合用例只验证优化前后输出等价，不证明五种语言均被完整正确识别，也不计入自然语料质量通过率。

同时确认：300 秒静音返回 NoSpeech 且未进入 decoding；处理中禁止切换；解码中取消在 **1,019 ms** 后收到已回收结果，恢复后英语转写成功；损坏 tokens 导致加载失败并恢复之前的候选；切回原图、切到 Whisper small、再切回候选均成功转写。直接协议测试覆盖两种 profile 互相错用时返回 InvalidTranscriptionProfile，之后用正确 profile 仍可转写。

首次跑快速连续短句发现阶段进度在不同 session 之间共用限流，导致后续任务缺少 decoding 提示。已将限流移入每次任务，完整序列重跑通过；每个 session 仍最多 5 次/秒。首次失败记录保留在开发缓存 `run-n4nkFO`，不计入通过证据。最终原始报告在 `run-xN6eoV`，摘要、配置与结果见 [worker 验证记录](./evidence/sensevoice-tiled-worker-2026-09-16.json)。

本轮没有采样内存，也没有启动 GUI 或麦克风；因此前文单进程内存数据仍不能代表完整应用峰值。原始权重、三个已签名模型条目和用户数据未更换。

## 重现

依赖只安装到开发缓存，不修改系统 Python 或产品运行时：

```sh
python3 -m pip install --target .cache/sensevoice/graph-study/python --no-deps onnx==1.17.0
PYTHONPATH=.cache/sensevoice/graph-study/python python3 scripts/diagnostics/sensevoice-tiled-attention.py --block 256
```

上一步打印独立的 `tiled-*` 目录。将其实际路径作为后续参数，不使用未经生成及校验的图：

```sh
python3 scripts/diagnostics/sensevoice-memory.py --modes default --repeats 3 --candidate-report .cache/sensevoice/graph-study/tiled-e0zkpzmp/report.json
python3 scripts/diagnostics/sensevoice-graph-compare.py .cache/sensevoice/graph-study/tiled-e0zkpzmp/report.json
```

生成器的局部代数检查需要开发环境已有的 NumPy 和 Python ONNX Runtime；报告记录实际版本。内存及多语言对照重新编译原生诊断程序，验证 native 库、C API header、模型、tokens 与音频的锁定摘要，推理完全离线。原图和候选依次在独立进程运行，不同时解码；原始文本只来自公开 fixtures，保留在开发缓存中。

真实 worker 专项检查同时需要已缓存的 Whisper small/VAD，使用构建生成的两个实际二进制：

```sh
SPEAKMORE_TEST_TILED_REPORT="$PWD/.cache/sensevoice/graph-study/tiled-e0zkpzmp/report.json" npm run test:asr:sensevoice:tiled
```

替换为实际导出的 256 行报告路径；该环境变量仅由显式运行的集成测试读取，产品没有此配置入口。测试校验生成报告、主文件精确身份和公开音频摘要；模型、tokens 与 VAD 再经产品加载校验。测试默认忽略，不混入日常轻量回归。原生诊断程序无 VAD；worker 对照包含实际首尾裁切，两组文本摘要不能直接混作同一个输入范围。

## 发布仍需满足的条件

已有证据包含候选图的局部数值、原生公开样本对照和上述 worker 专项检查。后续 [桌面会话与资源验证](./sensevoice-desktop-resources.md) 已覆盖真实 actor 导入、SQLite 重开、三次完整 300 秒及取消/切换，会话测试宿主与 worker 合计 RSS 最高采样值约 1.215 GiB。该检查不含 WebView 或真实麦克风，不能当作整应用 Gate。仍须完成可信发布源与签名版本目录、实际 GUI/IPC 设置链路、崩溃与升级恢复、整应用同步内存采样、连续 30 分钟使用、M1 8 GB/macOS 14，以及自然长音频和质量矩阵。五分钟限制、首尾覆盖要求和 small 整应用峰值 ≤2 GiB 门槛均保留。

不以重复公开片语证明自然语料准确率，也不以权重未改证明所有浮点输出必然一致。真实输出差异必须保留记录，不能只比较字数或删除差异 token 后宣称相同。实验没有使用生产模型签名密钥或签发新的下载目录。
