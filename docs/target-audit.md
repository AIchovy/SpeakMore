# 原生目标观察验收

此工具为 macOS 自动输入提供可重复的真实探测入口，复用产品的签名验证、AX 结构检查、选区/局部摘要、连续观察和独立复核。通过观察不等于通过粘贴验收，也不会给原生目标授予发布资格。

## 独立验证应用

```sh
npm run desktop:audit
```

生成 `target/release/bundle/macos/SpeakMore Input Check.app`，标识为 `com.speakmore.inputcheck.20260916`。构建必须显式使用 `target-audit` feature 和对应应用标识；界面通过独立的 Vite 构建开关载入。`npm run desktop:build` 强制关闭该界面开关，普通产品不会注册验证命令。

验证应用不启动产品 runtime、录音、模型 worker、数据库或剪贴板服务，不发送键盘事件。只有主窗口可以请求观察、取消及打开授权入口。应用启动只读取系统权限状态；点击“请求权限”才请求 macOS 显示辅助功能授权界面，工具自身不能修改 TCC 或授予权限。是否可用以系统实时检查为准，不从其他应用或麦克风权限推断。

点击“开始观察”后，原生计时器保留 8 秒切换到测试文稿；随后使用产品探测器捕获目标并连续观察 8 秒。结束前另发一次独立复核。界面仅显示固定结果、固定检查步骤和原生错误码；目标窗口标题、应用身份、文本片段和摘要不传到界面或磁盘。关闭窗口/退出会取消观察，取消和迟到结果不能恢复旧任务。始终只有一个目标探测线程，系统调用卡住时不另建线程。

## 合成文稿

- [plain.txt](./fixtures/target-audit/plain.txt)：纯文本，包含中文、英语、非 BMP 汉字、数字和多行。
- [rich.rtf](./fixtures/target-audit/rich.rtf)：相同合成文字的富文本版本。

这些文稿没有个人信息。用 TextEdit 打开其中一个，在观察期间保持对应窗口与光标稳定；变更测试才主动移动光标、改变选区或切换窗口。操作应用时应先确认当前窗口及控件，不能根据之前的元素序号操作新菜单或新页面。

## 用例与判定

| 用例 | 操作                                    | 期望                           |
| ---- | --------------------------------------- | ------------------------------ |
| P01  | 纯文本，中间光标，保持不动              | 捕获、连续观察及独立复核完成   |
| P02  | 纯文本，选中包含中文与非 BMP 字符的范围 | 保持原选区，观察与独立复核完成 |
| N01  | 富文本文稿                              | 在读取选区/上下文前拒绝        |
| N02  | 观察期间移动光标或改变选区              | 目标变化，切回原选区也不恢复   |
| N03  | 观察期间切换窗口后切回                  | 目标变化，不恢复               |
| N04  | 倒计时中取消                            | 不开始目标捕获，不出现迟到通过 |
| N05  | 观察过程中取消                          | 结束原生 lease，不出现迟到通过 |
| N06  | TextEdit 的查找框或其他不符合结构的控件 | 不读选区正文，保留不支持结果   |
| N07  | 目标关闭、权限不可用或读取超时          | 明确失败，不重试，不给通过状态 |

必须记录实际系统、TextEdit 版本、用例操作与原生结果；界面能打开、权限显示已允许、模拟目标 tests 或签名测试均不能作为上述用例的通过证据。

## 当前证据

2026-09-16，在 macOS 15.6.1 的 TextEdit 中实际观察到：空白纯文本窗口直接包含一个编辑区滚动容器和窗口控制；保存到文件的纯文本另有文稿图标。富文本增加格式工具栏和标尺。产品已加入有限层级/角色检查，允许一个文稿图标，拒绝工具栏、标尺、未知容器、多个编辑区及不匹配的父子关系。数组读取使用有界数量，不递归扫描任意控件树。这仍是候选结构，需要上表真实原生用例证明。

第一轮真实 P01 在 `AXFocusedApplication` 步骤返回目标不可用，尚未进入控件和选区检查；系统当时报告辅助功能可用。没有将这次失败计为通过。随后增加固定原生错误码诊断以定位原因；系统返回 `kAXErrorAPIDisabled` 时明确映射为需要辅助功能权限。补充文稿图标、复制后的数组计数复核及关闭取消后，完整桌面回归 **81 项通过、11 项按需忽略**。首次运行有 4 项因命令沙箱禁止回环监听失败，允许合成本机服务监听后完整重跑通过；没有跳过这些失败项。

固定的最终验证包 release 编译 **1 分 46 秒**，deep/strict codesign 检查通过；仍为 ad-hoc 签名。实际启动显示该构建辅助功能尚未授权，“开始观察”禁用，见[原生待授权界面](./screenshots/macos-target-audit-permission.jpg)。已请求用户确认开启该具体构建的权限，当前尚无回复；没有操作授权按钮或修改系统安全设置。需得到确认并检查实时授权后继续原生 P01/P02 和负向矩阵，不能据第一版曾报告已允许而沿用权限结论。

此阶段没有真实自动粘贴结果；设计 §16 的 I01–I09、C01–C02、物理快捷键/录音、浏览器与 VS Code、版本化兼容性清单及其余商业发布 Gate 仍需完成。
